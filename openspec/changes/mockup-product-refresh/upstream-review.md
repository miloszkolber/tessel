## Incorporation status

- Adapted `f74164eabda9` and `42cc8b93d059`: encoding-aware USB/fullPath/HTTP sidecar reads, early size rejection, truncated-response rejection, binary rejection, UTF-8 fallback, TXT sidecar discovery and MicroDVD/MPL2/TMPlayer parsing. Central European and Western/Cyrillic encoding detection remains heuristic. Headerless MicroDVD files at other frame rates can drift.
- Adapted `f09d39252c85`, `0e820532d4e6` and `00bc51bf90c6`: style/inline alignment, legacy SSA mapping, all active cues and embedded ASS placement. Local three-band overlay stays below menus and preserves queue/OSD clearance. Live position changes repaint active cues without resetting native-cue expiry. Absolute positioning, drawings and karaoke remain unsupported.
- Adapted `1b05169826e8`: app-language-first fallback, then untagged/sole sidecar. Explicit Off and per-file preferences are passed into the AVPlay pre-play selection rather than being temporarily overwritten by global preferences.
- Adapted `b292b5f4923b`: recursive music through the existing folder context menu and cancellable dialog. Source adapters retain their server IDs, sidecars and artwork. The walk caps concurrency, tracks, folders and depth, times out listings, rejects duplicates/cycles and ignores cancelled replies. Shuffling changes this queue only. No synthetic grid rows or extra settings were imported.
- Adapted `d8fd7d8f0d4d` and the focus-selection part of `0ba9ba4181a3`: Up restores the exited child. Fresh USB/SMB/WebDAV entry selects the latest played file or its successor after completion. Explicit return focus is retained. No watched-icon redesign, global centring or storage-key migration was imported.
- Adapted the duration consumer of `7a0896390d85`: USB-only MP4/MKV duration probing, two readers at a time, 15-second timeout, 256 reads/20 MiB per file, cancellation on navigation/playback, and a 400-record/131072-character disposable cache keyed by URI/size/mtime. The byte budget permits the existing Matroska 16 MiB header scan plus its separately capped 4 MiB Tracks element. MP4 skips payloads and reads only box headers plus the movie-duration field. Playback-reported USB durations fill unsupported containers. Durations append to the existing metadata line. Unused codec/track caches and speculative network probing were not imported.
- Adapted `d2078bb53abd`: folder context-menu history reset for USB/SMB/WebDAV, safe Cancel default, source/path-boundary matching and clearing watched/resume plus queue-only progress. Mixed queues retain unrelated items and progress. Media, pins and playback preferences remain untouched. Storage failures report failure and attempt rollback. No Left-key override was imported.
- Adapted safe parts of `4f895604d586`/`b7e975da0ee3`: staged single-file service wrapping, preserved lifecycle exports, idempotent listener startup, capability-gated modern module import, bounded import wait, legacy launch fallbacks and coalesced bounded loopback readiness checks. Added fail-closed loopback peer checks ahead of every credential-proxy route, including OPTIONS. The proxy binding and privileges remain unchanged. No own-IP probing, WebRTC probing, all-interface proxy listener, broad peer allow-list or extra feature gate was imported. The packaged service declaration keeps the TV-accepted shape (`type="service"`, no `web.service` feature): the one TV that received the fork rejected a build carrying the altered declaration, and the accepted shape matches the last-known-good upstream package. A LAN fallback is excluded without hardware evidence requiring it. Physical older-runtime/Tizen 10 startup remains unverified.
- Fork identity is `tesselfork.player` / package `tesselfork` (config.xml). The prior `tesselapp` package ID is refused by the deployment TV with `[118, -4] Load archive info fail` regardless of package bytes — proven by installing identical upstream bytes under three ID sets — so the fork does not use it. The service ID follows the package (`tesselfork.smbproxy`) via the existing dynamic derivation. Verified 2026-11-05 on QE65S90DATXXH (Tizen platform 9.0): Moonwalk-signed fork installs 0–100%, launches, lists alongside no other Tessel after the upstream `madebypatk.vlcweb` copy was uninstalled.
- A browser check exposed direct simulator resolution losing parent links and converting files into directories. The shim now rebuilds the real parent chain and preserves file kind, so direct folder Up restores the same child as normal browsing.
- Network access modes, Home restructuring and upstream release-workflow changes remain excluded as described above. The existing unsigned build workflow only gains the new service-wrapper script as a trigger and continues to call the same package command.

Focused software coverage exercises parsers, decoding, read bounds, overlaps, cancellation, path order, metadata fingerprints/budgets, history deletion isolation/rollback, service lifecycle/wrapping, peer denial and startup fallback. Browser layout checks use forced simultaneous-band fixtures separately from simulated playback checks. Neither establishes Samsung AVPlay or physical service acceptance.
